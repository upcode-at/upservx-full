## Release v0.5.0 - Security Module 🔐

**Release Date:** 2026-05-03

### 🎉 What's New in UpservX v0.5.0

This release introduces the **Security Module** — a dedicated administration area giving server operators a unified view of their system's security posture. Five features are bundled in a single tabbed interface accessible to admin-group users: Fail2Ban management, package upgrade tracking, SSL/TLS certificate inspection, open port scanning and CVE vulnerability scanning via the OSV.dev database.

---

### ✨ New Features

#### 🛡️ Fail2Ban Management
Monitor and manage Fail2Ban directly from the dashboard.

- All configured jails are listed with name, status (active / inactive), currently banned IP count and total failed attempts
- Each jail shows its full list of currently banned IPs in a table
- **Unban** action per IP — calls `fail2ban-client set <jail> unbanip <ip>` via the backend and refreshes the view
- Graceful error display on systems where Fail2Ban is not installed or not running

**Backend:** `get_all_fail2ban_jails()` — iterates `fail2ban-client status`, then fetches detail for each jail

---

#### 📦 Package Upgrade Tracker
Track and apply pending security and maintenance package updates (Debian/Ubuntu only).

- Lists all upgradeable packages via `apt-get --simulate upgrade`, showing package name, current version, target version and whether the update is classified as a security fix
- **Security-only filter** — toggle to show only packages with `security` in their repository source
- **Update All** — triggers `apt-get upgrade -y` non-interactively with a 5-minute timeout; spinner during execution
- **Per-package Update** — `POST /security/packages/upgrade/{name}` upgrades a single package; package name validated with `^[a-zA-Z0-9][a-zA-Z0-9.+\-]*$` to prevent injection
- Non-Debian systems show an informational note instead of an error

**Backend:** `get_upgradeable_packages()` + `upgrade_package(package_name=None)`

---

#### 🔏 SSL/TLS Certificate Inspector
Scan the filesystem for X.509 certificates and inspect their validity.

- Scans `/etc/ssl/`, `/etc/nginx/`, `/etc/letsencrypt/`, `/etc/apache2/` and `/etc/haproxy/` for `.crt` and `.pem` files containing valid certificates
- For each certificate: displays common name, issuer organisation, expiry date, days remaining and a status badge
- **Status badges:** `VALID` (green) / `EXPIRING SOON` (< 30 days, amber) / `EXPIRED` (red)
- **Status filter toolbar:** show All / Expired / Expiring soon / Valid certificates
- **Sort by days remaining** — toggle ascending/descending via a toolbar button or by clicking the *Days Left* column header

**Backend:** `get_certificates()` — uses `openssl x509` to parse each file

---

#### 🌐 Open Port Scanner
See all currently listening network ports at a glance.

- Runs `ss -tlnpu` to list all TCP and UDP ports in LISTEN state
- Shows protocol, local address, port number, process name and PID
- **Protocol filter:** All / TCP / UDP
- **Address filter:** All / Public (non-loopback) / Loopback (`127.x.x.x` / `::1`)
- Filtered result count shown as a badge on the toolbar

**Backend:** `get_open_ports()` — parses `ss` output and resolves process names via `ps`

---

#### 🐛 CVE Vulnerability Scanner
Scan installed packages against the [OSV.dev](https://osv.dev) open-source vulnerability database.

- Manual scan trigger (no auto-load) — click **Start Scan** to begin
- Queries the OSV.dev `/v1/querybatch` API in batches of 100 packages for low-overhead lookups
- Results show: CVE / OSV ID, affected package, CVSS score (V2/V3/V4 — highest available), severity badge and advisory summary
- Sorted by severity (Critical → High → Medium → Low → Unknown) then by CVSS score descending
- **Severity filter buttons:** All / Critical / High / Medium / Low
- External advisory links open in a new tab where available

**Backend:** `scan_cves(limit=300)` — uses `dpkg-query` to enumerate installed packages, batches OSV queries via `urllib`

### 🖥️ Frontend

**New component:** `components/security.tsx`

- 5 tabs: Fail2Ban · Packages · Certificates · Open Ports · CVE Scan
- 5 summary cards at the top of the page (jails, expiring certs, open ports, upgradeable packages, CVEs found)
- All data loads on tab switch (lazy loading per tab); CVE tab requires explicit "Start Scan" action
- Unified `NotificationContainer` for loading errors and success messages
- Full filter and sort controls per tab (see above)

**Sidebar:** New **Security** entry in the *Administration* section (requires `admin` / `sudo` / `wheel` group), icon: ShieldAlert

### ⚙️ API Changes

**New router prefix: `/security`** (requires admin group)

| Method | Path | Description |
|---|---|---|
| `GET` | `/security/fail2ban` | All Fail2Ban jails with banned IPs |
| `POST` | `/security/fail2ban/unban` | Unban an IP from a jail |
| `GET` | `/security/packages` | Upgradeable package list |
| `POST` | `/security/packages/upgrade` | Upgrade all packages |
| `POST` | `/security/packages/upgrade/{name}` | Upgrade a single package |
| `GET` | `/security/certificates` | SSL/TLS certificate inventory |
| `GET` | `/security/ports` | Open port list |
| `GET` | `/security/cve?limit=300` | CVE scan results (limit: 50–1000) |

**`GET /security/fail2ban` response example (per jail):**
```json
{
  "name": "sshd",
  "active": true,
  "banned_count": 3,
  "total_failed": 142,
  "banned_ips": ["192.168.1.5", "10.0.0.7", "203.0.113.9"]
}
```

**`POST /security/fail2ban/unban` request body:**
```json
{ "jail": "sshd", "ip": "192.168.1.5" }
```

**`GET /security/certificates` response example (per cert):**
```json
{
  "path": "/etc/letsencrypt/live/example.com/cert.pem",
  "common_name": "example.com",
  "issuer": "Let's Encrypt",
  "expiry": "2026-07-15",
  "days_left": 73,
  "status": "valid"
}
```

**`GET /security/cve?limit=300` response example (per finding):**
```json
{
  "id": "CVE-2024-12345",
  "package": "openssl",
  "version": "3.0.2",
  "cvss_score": 9.8,
  "severity": "critical",
  "summary": "Heap buffer overflow in OpenSSL X.509 parsing"
}
```

### 📦 Upgrade Notes

No database migration or configuration changes are required. The security router registers automatically on backend startup.

**Dependencies:**
- **Fail2Ban:** requires `fail2ban` to be installed and `fail2ban-client` to be executable by the backend user. Non-present installations are handled gracefully (no crash, informational message shown).
- **Package scanner:** requires `apt-get` — Debian/Ubuntu/Raspberry Pi OS only. Non-Debian systems display an informational note.
- **Certificate scanner:** requires `openssl` binary (available on all major distributions).
- **Port scanner:** requires `ss` from `iproute2` (standard on all modern Linux distributions).
- **CVE scanner:** requires outbound HTTPS access to `api.osv.dev`. No API key needed.

**Access control:** All `/security/*` endpoints require admin group membership (`sudo` or `wheel`). The Security item in the sidebar is hidden for non-admin users automatically.
